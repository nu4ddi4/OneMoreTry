## GitHub 검증

`Godot Windows` 워크플로가 PR마다 `Branch policy`, `Test & export Windows`, `Windows launch` 검사를 실행합니다. Windows 실행 검사는 Windows runner에서 배포 EXE를 headless로 실행하고 종료 코드와 Godot 오류 로그를 확인합니다. 화면 캡처는 Linux OpenGL에서 수행하며 Windows에서의 수동 키보드·오디오·GPU 호환성 확인은 별도 플레이 테스트가 필요합니다.

2026-10-30 [최초 원격 검증](https://github.com/nu4ddi4/side-scroller-game/actions/runs/41019589797)에서 세 작업이 모두 성공했습니다. Windows runner에서 실제 내보낸 `OneMoreTry.exe`의 종료 코드 0과 런타임 오류 없음도 확인했습니다. 이후 커밋과 병합 커밋에도 같은 워크플로가 재실행됩니다.

`main`과 `beta` 브랜치를 생성했고, `feature/godot-mvp → beta → main` PR 흐름으로 최초 배포합니다. CI에서 잘못된 PR 방향을 실패 처리합니다.

서버 측 강제 보호 설정은 연결된 GitHub 앱의 권한 제한으로 적용하지 못했습니다. `PUT /repos/nu4ddi4/side-scroller-game/branches/beta/protection`이 **HTTP 403: Resource not accessible by integration**을 반환했습니다. 따라서 현재 CI 실패 상태라도 관리자가 병합하거나 직접 push하는 동작까지 강제로 차단하지는 못합니다. 관리 권한이 있는 GitHub CLI에서 `python3 tools/configure_branch_protection.py`를 실행하면 두 브랜치의 PR 필수화, 세 CI 검사 필수화, 강제 push·삭제 금지를 적용할 수 있습니다. 승인자 수는 0으로 두어 단독 개발자도 검사 통과 후 병합할 수 있습니다.

## v0.2.1에 포함된 창 맞춤 및 안내 제거

시작 창 모드를 최대화로, 화면 배율을 fractional로 변경했습니다. F11을 다시 누르면 전체 화면 진입 전의 창 모드로 돌아갑니다. 안내 팻말 6개와 비밀 길 안내 문구를 제거했고 실제 캡처로 README 이미지를 갱신했습니다. 새 함정은 `docs/TRAP_DESIGN.md`에 설계만 정리했으며 현재 스테이지의 함정 배치와 동작은 변경하지 않았습니다.

Linux X11/Xvfb와 Openbox의 소프트웨어 OpenGL 창에서 최대화 시작(mode 2), F11 전체 화면(mode 3), 최대화 복귀(mode 2)를 확인했습니다. 960×540·1280×720·1600×900의 16:9 창에서 렌더 영역이 각각 창 크기와 일치하고 메뉴·HUD가 잘리지 않는 것을 확인했습니다. 다른 종횡비에서는 960×540의 논리 화면 비율을 유지하므로 작은 여백이 생길 수 있습니다. Windows 장치의 대화형 창 동작은 별도 확인 범위이며 CI에서는 Windows 내보내기·설치·기동을 검증합니다.

기존 게임 검사 58개, 업데이트 검사 54개, 일반 입력 스테이지 노데스 통과(14.81초)를 다시 확인했습니다. 점프 설계에 사용한 평지 높이·거리는 `tools/probe_jumps.gd`로 재현할 수 있으며, 설계 단계인 새 함정의 통과를 증명하는 결과는 아닙니다.

- `tests/display_tests.gd`: **103개 검사 통과**. 640×360, 800×600, 1024×768, 1280×800, 1366×768, 1920×1080, 2560×1080, 3440×1440, 3840×1080, 3840×2160에서 뷰포트 채움, 메뉴·HUD·일시정지·기록·클리어의 화면 경계, 카메라 좌우 경계, 작은 화면의 업데이트 창과 단축키 차단, 창 크기 변경 후 대화상자 위치를 검사합니다.
- Linux X11/Openbox·Mesa 소프트웨어 OpenGL에서 렌더 캡처와 F11 왕복을 확인했습니다. 일반 창→전체 화면→일반 창, 최대화→전체 화면→최대화가 모두 통과했습니다. 해당 렌더 행렬은 97개 검사를 통과했으며, 후속으로 추가한 클리어 화면 행렬은 위 103개 검사와 별도 렌더 캡처로 확인했습니다.
- 게임 회귀 **62개 통과**. 저장 실패를 호출부에 전달하고 클리어 화면에서도 오류 메시지를 유지합니다. 종료 시 저장 실패를 감추지 않으며, 취소에 기본 초점을 둔 종료 선택 창을 표시합니다. 파일 쓰기/flush 오류가 있으면 기존 기록 파일을 교체하지 않습니다.
- 업데이트 실제 HTTP 검사 **84개 통과**. 설치 파일이 없는 새 베타를 "업데이트 없음"으로 처리하지 않고 재시도 가능한 오류로 표시합니다. 이미 받은 설치 파일은 크기·SHA-256을 다시 확인해 재사용하고, 손상된 캐시는 새 검증 파일로 교체합니다. 채널 선택 유지와 다운그레이드 차단 검사는 그대로 통과합니다.
- 일반 입력 전체 스테이지 통과 **14.81초, 실패 0회, 비밀 별 및 체크포인트 2개**. 물리 지형과 함정 배치는 변경하지 않았습니다. 릴리스 설정 검사와 해당 Actions 파일의 actionlint도 통과했습니다. 새 한국어 문구는 포함 폰트에서 모두 표시할 수 있습니다.

현 세션 캡처 및 단계별 시각 점검 보고서는 `build/display-audit/report.html`에 생성했습니다. 스크린샷은 메뉴·플레이/HUD·일시정지·기록·클리어·업데이트·저장 실패 종료의 현재 렌더 화면입니다. 테스트는 별도 사용자 기록 경로를 사용합니다. Windows CI는 설치·재설치·설치본 실행·제거·기록 보존과 작은 창/울트라와이드 크기의 배포 EXE 기동을 검사합니다. 실제 Windows 모니터의 DPI·GPU·다중 모니터 이동 및 스크린 리더 동작은 이 환경에서 직접 확인하지 못했습니다. 작은 창에서는 글자가 작아지므로 가독성을 위해 최대화 사용이 적합합니다. 접근성 준수를 인증하는 결과는 아닙니다.
