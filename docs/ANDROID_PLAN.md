# Android 검토 — 0.5.0 기준

결론: Godot와 같은 프로젝트를 유지한다. 공통 요소와 조작 규칙을 정리한 현재 기반을 사용하고, 앞으로 예정한 이동/기믹 수정이 안정될 때 비공개 테스트 APK를 만든다. 지금부터 Windows와 Android의 정식 배포를 모두 운영하면 변경마다 터치·기기·설치 검수가 추가된다. 코드가 두 벌이 될 필요는 없지만 작업량이 전혀 늘지 않는 것은 아니다.

## 현재 재사용할 수 있는 부분

- GDScript, 2D 노드, 공통 충돌/렌더러는 Android에서도 사용하는 Godot 구성이다. 현재 Compatibility 렌더러와 모바일 Compatibility 설정을 사용한다.
- 이동·점프·오르내리기는 InputMap 액션으로 모여 있다. 터치 입력을 같은 액션으로 보내면 물리를 복제할 필요가 없다.
- 창 크기 확장, 뷰포트 기반 HUD/메뉴 배치는 이미 적용되어 있다. 다만 데스크톱 해상도 검사가 휴대폰의 안전 영역이나 터치 조작 검증을 대체하지 않는다.
- Windows 업데이트 버튼/자동 검사와 EXE 실행은 운영체제 조건으로 제한되어 있다. Android에 Windows 설치 프로그램을 내려받게 연결하지 않는다.

## APK를 만들 때 추가할 작업

1. 가로 화면에서 좌우 이동과 점프·상하 사슬/벽 조작의 동시 멀티터치. 손가락이 함정/착지를 가리는 정도, 버튼 크기와 여백을 실제 기기로 검사한다. 현재 키보드 중심 난이도는 터치에 맞춰 다시 평가한다.
2. 노치/카메라/시스템 제스처 안전 영역, 긴 화면비, 뒤로 가기와 일시정지. 앱 전환·화면 잠금·복귀에서 입력 해제, 시간 정지, 소리와 기록 보존을 확인한다.
3. 저사양 기기에서 120Hz 물리와 현재 사용자 정의 그리기를 측정한다. 측정 전 물리 주기를 바꾸지 않는다. 변경이 필요하면 이동/사슬/타이머와 전체 재생 검사를 함께 확인한다.
4. 공식 Android 내보내기 템플릿, OpenJDK 17과 Android SDK, 패키지 ID, 가로 방향 프리셋, 버전 코드, 적응형 아이콘을 준비한다. 배포용 서명 키는 저장소에 넣지 않는다.
5. 초기에는 테스트 APK 수동 설치로 검증한다. 정식 배포 시 Play 배포 또는 별도 APK 설치 흐름을 결정하며 Windows EXE 자동 업데이트 코드를 재사용하지 않는다. 재설치·업데이트의 서명 일치와 저장 기록 유지도 별도로 검사한다.

현재 저장소에는 Android 프리셋/터치 UI가 없고 이 개발 환경에는 adb/Android SDK가 준비되어 있지 않다. 이번 변경은 APK나 휴대폰 성능 검증을 포함하지 않는다.

## 권장 순서

공통 요소 통일(이번 변경) → 남은 PC 이동/기믹 수정 → 실제 휴대폰에서 터치 시제품 APK → 기기별 성능/화면 검증 → 필요할 때 Android 배포 자동화. 소스 브랜치나 게임 로직을 플랫폼별로 복제하지 않고 입력 UI·OS 기능·내보내기 프리셋만 분리한다.

근거: [Godot 4.6 Android 내보내기 공식 문서](https://docs.godotengine.org/en/4.6/tutorials/export/exporting_for_android.html), [같은 공식 소스](https://github.com/godotengine/godot-docs/blob/4.6/tutorials/export/exporting_for_android.rst). JDK/SDK와 서명 요구 사항은 배포 시 공식 문서의 현재 버전을 다시 확인한다.
