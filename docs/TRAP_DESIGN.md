# 함정 개편 설계 — 처음엔 죽고, 다음엔 의심하게

상태: **설계안. 아래 새 함정은 아직 구현하지 않았다.** 이번 beta 변경은 시작 창 최대화·화면 배율 수정·안내 팻말 제거까지다. 다음 구현의 우선순위는 1~3번 함정을 연결한 구간이다.

## 방향

첫 도전에서는 예상 밖의 기습으로 죽는다. 다음 도전에서는 기억한 해법으로 살아남지만, 이어지는 함정은 그 해법을 역이용한다. 단순히 가시를 늘리거나 경고 시간을 줄이는 방식으로 끝내지 않는다.

현재 스테이지는 팻말, 금 간 발판, 발동 전 경고, 한 번의 긴 점프로 넘는 구간이 많다. 새 구간은 플레이어가 **당연히 할 행동**을 먼저 정한 다음, 그 행동이 사망을 일으키도록 구성한다. 플레이 전에는 함정의 해법을 설명하지 않는다. 첫 죽음에서 실제 장치와 움직임을 보여 주고 다음 도전에서 공략하게 한다.

- 먼저 미끼와 플레이어의 예상 행동을 설계한다.
- 첫 실패에서 가장 자연스러운 행동을 확실하게 잡는다.
- 한 번 성공한 행동을 다음 구간에서 그대로 반복하면 다시 죽게 한다.
- 살아남는 입력 순서를 정하고, 실제 입력만으로 통과시키고 나서 난이도를 확정한다.
- 무작위 발동, 사망 횟수에 따른 규칙 변경, 창 크기에 따른 함정 노출 차이는 넣지 않는다. 같은 입력과 위치라면 같은 함정이 나온다.
- 실제 체크포인트의 저장과 실제 클리어 판정은 일관되게 유지한다. 가짜 연출에서는 기록을 저장하거나 입력을 잠그지 않는다.

## 현재 조작으로 가능한 범위

Godot 4.6.3, 물리 120Hz, 평지에서 오른쪽 최고 속도 250px/s를 유지하며 현재 플레이어 코드로 측정했다. 아래 수치는 실제 캐릭터의 발 위치 기준이다. 새 함정의 통과 검증 결과가 아니다.

측정 재현: `godot --headless --fixed-fps 120 --script tools/probe_jumps.gd -- --test`. 실제 사용자 기록은 읽거나 쓰지 않는다.

| 점프 키 유지 | 최고 높이 | 평지 착지까지 이동 | 비행 프레임 |
| --- | ---: | ---: | ---: |
| 1프레임 | 21.0px | 87.5px | 42 |
| 6프레임 | 35.4px | 108.3px | 52 |
| 12프레임 | 50.3px | 125.0px | 60 |
| 20프레임 | 66.3px | 143.8px | 69 |
| 45프레임 | 86.7px | 183.3px | 88 |

긴 점프와 짧은 점프의 차이를 함정의 해법으로 사용한다. 120Hz에서 1프레임은 약 8.33ms다. 공략을 안 뒤의 주요 입력 구간은 우선 **8프레임 이상**을 목표로 잡고 실제 장면에서 검증한다. 첫 도전의 기습을 순발력만으로 피할 수 있게 만들 필요는 없다.

## 여덟 개의 함정

| 순서 / 이름 | 믿게 만드는 것 | 처음 죽는 방식 | 기억한 뒤의 해법 |
| --- | --- | --- | --- |
| 1. 첫 점프 수금 | 아무것도 없는 평지에서 점프해 본다 | 점프하거나 공중으로 진입하면 머리 위 턱이 닫힌다 | 200px 구간을 점프 없이 걷는다 |
| 2. 도착지는 없다 | 작은 구덩이는 길게 뛰면 안전하다 | 공중에서 중간선을 넘으면 넓은 착지판이 빠진다 | 앞쪽 작은 발판에 짧게 착지한 뒤 두 번째 점프 |
| 3. 걷기만 하면 죽는다 | 1번에서 배운 대로 낮은 천장 아래를 걷는다 | 뒤에서 나온 칼이 따라잡는다. 일찍 뛰면 천장에 죽는다 | 천장 끝을 지난 직후 짧은 시간 안에 점프 |
| 4. 안전한 대기실 | 압착기가 있으니 그 아래 움푹한 곳에서 기다린다 | 대기실 바닥이 늦게 열리고, 당황해서 뛰면 천장에 닿는다 | 장치를 입구 바깥에서 발동시키고 밖에서 기다린다 |
| 5. 체크포인트 다음 한 발 | 저장됐으니 바로 앞으로 달린다 | 출구 쪽에서 칼이 날아오고 점프 경로는 막혀 있다 | 트리거를 건드린 뒤 방금 지나온 안전 공간으로 물러난다 |
| 6. 발판은 먼저 간다 | 움직이는 발판의 진행 방향으로 뛰어야 한다 | 도약 중 발판이 반대쪽으로 이동해 예상 착지점이 빈다 | 도약 후 반대로 제동해 원래 발판 쪽으로 착지한다 |
| 7. 골인했지? | FINISH 문을 지났고 짧은 성공음이 들린다 | 손을 떼는 순간 문 아래 바닥이 열린다 | 문을 지나 52px 이상 계속 이동한다 |
| 8. 방금 배운 것도 틀렸다 | 7번에서 배운 대로 계속 달린다 | 조금 앞의 낙하 블록에 맞는다. 미리 뛰어도 낙하 경로와 겹친다 | 가짜 문을 벗어난 뒤 멈추고, 블록이 떨어진 후 뛰어넘어 실제 출구로 간다 |

4~8번은 후속 구현 후보다. 각 장치의 상세 배치와 유효 입력 구간은 프로토타입에서 확정한다. 아래 1~3번도 수치는 첫 배치안이며, 현재 스테이지가 이미 이렇게 동작한다는 뜻은 아니다.

## 먼저 구현할 구간: 1~3번 연쇄

기존 전체 길이 3600px와 첫 체크포인트 x=1460을 기준으로 앞부분을 재구성한다. 현재 지형을 그대로 두고 함정만 얹으면 통과 불가능한 구간이 생길 수 있으므로 지형과 함정을 함께 교체한다.

### 1. 첫 점프 수금 — x=220~420

- 미끼: 평범한 잔디 바닥. 안내 문구와 선행 경고음이 없다.
- 발동: 이 범위에서 점프하거나 공중 상태로 들어온다. 점프를 밖에서 시작해도 공중 진입을 감지한다.
- 공격: 첫 프레임에 턱이 나타나고 3번째 물리 프레임부터 실제 충돌 영역을 활성화한다. 후보 영역은 x=220~420, y=368~384다.
- 실패: 작은 점프로도 턱에 닿는다. 구간 길이가 최대 점프 거리보다 길어서 긴 점프로 천장 위를 통째로 넘는 방식도 막는다.
- 해법: 그냥 걷는다. 현재 피격 영역의 머리는 평지에서 y=389라서 닫힌 턱 아래로 걸을 공간이 남는다.
- 재시도: 실제 체크포인트에서 돌아오면 턱과 발동 상태를 초기화한다. 이후 시도에서도 같은 입력에는 같은 공격이 나온다.
- 필수 검증: 평지 보행 통과, 구간 안의 짧은/긴 점프 사망, 구간 밖에서 뛰어드는 우회 사망, 경계에서 부당한 접촉 없음.

### 2. 도착지는 없다 — 구덩이 시작 x=640

후보 지형:

| 구간 | 범위 | 역할 |
| --- | --- | --- |
| 출발 바닥 | x<640 | x≈632에서 도약하는 기준선 |
| 구덩이 | x=640~712 | 짧은 점프로도 넘을 수 있는 폭 72px |
| 실제 작은 발판 | x=712~752 | 끝까지 남는 폭 40px의 첫 착지점 |
| 넓은 가짜 착지판 | x=752~848 | 길게 뛰면 도착할 것처럼 보이는 곳 |
| 실제 다음 바닥 | x≥848 | 두 번째 점프로 도달하는 곳 |

- 발동: 공중에서 x=676을 넘을 때 가짜 착지판이 빠진다. 정지·후퇴·사망 횟수로 재배치하지 않는다.
- 실패: 최고 속도로 길게 뛰면 약 x=815에 내려오지만, 착지판은 이미 없다. 화면에는 빠지는 발판을 남겨 무엇에 속았는지 보이게 한다.
- 해법: 약 6프레임 유지한 점프로 x≈740의 작은 발판에 착지하고, 다시 점프해 x≥848로 넘어간다. 현재 평지 측정상 두 번째 점프를 약 12프레임 유지하면 x≈865에 도달한다.
- 연쇄의 의미: 1번은 점프를 금지했지만 여기서는 두 번 점프해야 한다. 바닥의 생김새만 믿고 한 번에 뛰면 죽는다.
- 필수 검증: 한 번의 긴 점프가 가짜 판에 떨어지는지, 짧은 두 번 점프로 통과하는지, 실제 작은 발판의 착지/재도약 입력 여유가 충분한지 실제 물리로 확인한다. 위 착지 좌표는 출발 속도와 실제 충돌에 따라 달라질 수 있다.

### 3. 걷기만 하면 죽는다 — x=880~1080

- 미끼: x=880~1000의 낮은 천장. 1번에서 배운 대로 걷고 싶게 만든다. 천장은 보행 가능한 높이에 있고 점프하면 실제로 닿는다.
- 발동: 플레이어가 x=960을 지나면 x=880에서 지면 높이의 칼이 출발한다. 후보 속도는 450px/s, 칼 높이는 약 20px다.
- 실패 A: 계속 걸으면 뒤의 칼이 따라잡는다.
- 실패 B: 칼이 보이자마자 뛰면 아직 낮은 천장 아래라 머리를 부딪친다.
- 해법: 천장 끝을 빠져나온 직후 점프한다. 최고 속도로 진행할 때 천장을 벗어나는 시간은 약 24프레임이고, 칼이 따라잡는 시간은 피격 영역을 고려하면 약 39프레임이다. 떠오르는 시간을 빼고도 약 8프레임 이상의 도약 구간이 남도록 조정한다.
- 튜닝: 위 시간은 초기 계산이다. 칼 너비·천장 끝·플레이어 콜라이더·입력 버퍼를 넣은 실제 장면에서 입력 허용 구간을 측정해 확정한다.
- 필수 검증: 걷기 사망, 너무 이른 점프 사망, 정해진 구간의 점프 통과, 최소 입력 허용 구간 확보, 일시정지 중 칼·발동 시간이 정지하는지 확인한다.

이 연쇄는 **점프하면 죽음 → 길게 뛰면 죽음 → 안 뛰면 죽음**으로 기억한 답을 바꾼다. 세 함정의 해법을 잇는 실제 입력 테스트가 통과하면 체크포인트를 둔다.

## 후반의 핵심: 가짜 골인과 마지막 반전

7번 가짜 문은 실제 출구와 같은 문양과 FINISH 표기를 사용한다. 먼저부터 물음표나 다른 색으로 가짜임을 알려 주지 않는다. 통과 시 짧은 성공음은 재생하지만 게임 상태는 PLAYING으로 남기고, 클리어 기록·입력 잠금·클리어 화면은 실행하지 않는다.

초기 후보는 x=3120의 가짜 문, x=3120~3152의 바닥, 통과 후 24프레임에 열리는 타이밍이다. 계속 달린 플레이어는 약 50px 전진해 바닥을 벗어나고, 멈춘 플레이어는 떨어진다.

그다음 낙하 블록은 계속 달리면 맞는 경로에 둔다. 해결 순서는 문 통과 → 약 52px 전진 → 제동 → 블록 낙하를 기다림 → 블록을 점프로 넘음 → 실제 출구 x=3384다. 블록의 폭·높이와 낙하 시작 시간은 현재 약 183px/86.7px의 최대 점프 범위로 넘을 수 있도록 검증한다. 블록을 피해 벽 밖으로 나가거나 정해진 입력을 넣어도 필연적으로 죽는 배치는 버린다.

## 구현할 때 고정할 규칙

1. 장치별 미끼, 발동 조건, 첫 사망, 공략 입력, 초기화 조건을 함께 기록한다.
2. 위험 판정은 보이는 물체의 영역에 둔다. 숨겨 둔 공격은 발동 후 모습을 드러낸다.
3. 같은 구간을 반복할 때 공격 타이밍을 바꾸거나 정답을 사망 횟수에 따라 갈아 끼우지 않는다.
4. 실제 체크포인트는 확실하게 저장하고, 부활 위치와 트리거를 분리해 부활 직후 자동 사망을 막는다.
5. 장치의 시간은 게임 물리 시간으로 진행한다. 일시정지·메뉴·클리어 중에는 공격이 진행되지 않는다.
6. 카메라·창 크기·모니터 비율로 먼저 보이는 정보가 달라지지 않도록 논리 화면은 960×540을 유지한다.
7. 처음 보는 자연스러운 입력이 사망하는 테스트와, 정답을 아는 입력이 통과하는 테스트를 둘 다 만든다. 플레이어 위치를 순간 이동시킨 테스트만으로 통과를 주장하지 않는다.
8. 1~3번 연쇄의 전체 입력 재현, 경계 입력, 부활, 중간 일시정지 검증이 끝나면 4~8번을 확장한다.

게임 함정/레벨 디자인 전용 연결 스킬은 현재 없다. 이 문서의 규칙과 함정별 항목을 다음 설계에서도 반복 사용하는 검토 기준으로 삼는다.
